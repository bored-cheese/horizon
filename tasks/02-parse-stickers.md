# Задача 2. Разбор новых стикеров и связей

> Требует инструкций проекта «Горизонт»: разделы «Что такое потребность»,
> «Геометрия фрейма» и «Как писать». Вне проекта задача работать не будет.

**Пишет на доску:** да — правит текст стикеров и цвет связей.
**Пишет в таблицу:** да — добавляет строки.
**Периодичность:** вручную, после добавления стикеров.

## Что прочитать

Из таблицы «Реестр потребностей» три коротких чтения:

1. Строки, где `type` = root: их `id` и `needs`.
2. Максимальный `id` в таблице.

С доски — только стикеры внутри фрейма «Горизонт планирования» и линии
между ними.

Стикеры за пределами фрейма не трогай. Стикеры без текста пропускай.

## Часть 1. Новые стикеры

Найди стикеры без ID в тексте — это новые потребности, добавленные вручную.

Каждый сначала проверь на признак решения и на признак хотелки.
Не прошло проверку — строку не заводи, вынеси на уточнение с предложением, как переформулировать.

Для прошедших проверку:

1. Определи год по центру стикера, из года — период.

2. Определи важность и `type` по дорожке, в которой лежит стикер.

3. Заведи строку: присвой `id` на единицу больше максимального в таблице, проставь `type`, `period`, `importance`, текст стикера положи в `needs`.

4. Заполни `p_id` — id корневой потребности, ради которой существует эта. Бери только из прочитанных строк с `type` = root. Если подходят две — оставь пусто и вынеси на уточнение с обеими. Если корневых в таблице ещё нет — оставь пусто, это не ошибка.

5. Остальные колонки оставь пустыми — их заполнит задача 3 по комментариям.

6. Перепиши текст стикера, добавив в начало присвоенный id и разделитель « · ». Если текст стикера обёрнут в ссылку, сохрани обёртку: id должен войти внутрь ссылки, а не заменить её.

## Часть 2. Связи

Прочитай линии, соединяющие стикеры. Сначала посмотри, лежит ли хоть один конец линии в серой зоне корневых.

**Один конец линии в серой зоне корневых.** Это принадлежность, не зависимость. Правь строку НЕ-корневого стикера. Колонка — `p_id`. Значение — `id` корневого стикера. Одно число, не список.
Строку корневого стикера не трогай вообще: у корневых `depends on`
всегда пустой, они ни от чего не зависят.
Цвет линии поменяй на `#e7e7e7`.

**Оба конца в цветных дорожках** — это зависимость по времени.
Кто ниже, тот наступает раньше и является предшественником: запиши id нижнего в `depends on` верхнего.
 
Сравнивай центры по вертикали, а не годовые полосы. Два стикера в одной полосе почти всегда стоят на разной высоте, и этого достаточно.

Если центры совпадают с точностью до нескольких пикселей, направление не определяется. Связь всё равно зафиксируй: запиши в `Примечания` обоих «связь с N, направление не определено» и вынеси пару на уточнение.
Перед записью посмотри, что уже лежит в ячейке. Если id там уже есть — не добавляй повторно. Если в ячейке есть id, которому не соответствует ни одна линия на доске, — не удаляй его, а вынеси в список расхождений: возможно, связь проставлена вручную.

## Что вернуть

1. Заведённые строки.
2. Отложенные на уточнение: решения вместо потребностей и хотелки.
3. Связи без определимого направления.
4. Расхождения по связям: id, который стоит в `depends on` или `p_id`,
   но которому не соответствует ни одна линия на доске.
