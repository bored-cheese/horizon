# Задача 2. Разбор новых стикеров и связей

> Требует инструкций проекта «Горизонт»: разделы «Что такое потребность»,
> «Геометрия фрейма» и «Как писать». Вне проекта задача работать не будет.

**Пишет на доску:** правит текст стикеров и цвет линий.
**Пишет в таблицу:** добавляет строки, заполняет `дети` и `depends on`.
**Периодичность:** вручную, после добавления стикеров.

## Что прочитать

Из таблицы «Реестр потребностей» — все строки: `id`, `type`, `needs`,
`дети`, `depends on`, `Примечания`. И максимальный `id`.

С доски — **чтением по области**, охватывающей весь фрейм «Горизонт
планирования». Не по списку идентификаторов: соединители при точечном
чтении не возвращаются, а они нужны.

Из прочитанного бери:
- стикеры внутри фрейма: их `data-miro-id`, координаты, размер, цвет, текст;
- линии: их `data-miro-id`, `data-start`, `data-end` и текущий `stroke`.

Стикеры за пределами фрейма не трогай. Стикеры без текста пропускай.

## Часть 1. Новые стикеры

Найди стикеры без ID в тексте — это новые потребности, добавленные вручную.

Каждый сначала проверь на признак решения и на признак хотелки.
Не прошло проверку — строку не заводи, вынеси на уточнение
с предложением, как переформулировать.

Для прошедших проверку:

1. Определи год по центру стикера, из года — период.
2. Определи важность и `type` по дорожке, в которой лежит стикер.
3. Заведи строку: `id` на единицу больше максимального в таблице,
   проставь `type`, `period`, `importance`, текст стикера положи в `needs`.
4. Остальные колонки оставь пустыми.
5. Перепиши текст стикера, добавив в начало присвоенный id и разделитель
   « · ». Если текст обёрнут в ссылку, id должен войти внутрь обёртки,
   а сама обёртка сохраниться.

Родителя в этой части не определяй — он берётся только из линий.

## Часть 2. Классификация линий

Ничего не записывай, пока не выпишешь весь список.

Для каждой линии определи id стикеров на обоих концах — он написан
в начале текста стикера, до разделителя « · ». Посмотри `type` этих
потребностей в таблице и составь строку отчёта:

    id линии | id_A (type_A) — id_B (type_B) | случай

Случай определяется только по `type`, положение стикеров не смотри:

- **Р** — ровно один конец `root`. Это родительство.
- **З** — оба конца `derivative`. Это зависимость.
- **Х** — оба конца `root`. Схемой не предусмотрено.

Выведи полный список. Дальше работай строго по нему.

## Часть 3. Родительство (случай Р)

Для каждой линии случая Р:

- В строку **корневой** потребности, колонка `дети`: добавь id второго
  стикера. Если там уже есть значения — допиши через запятую,
  не затирай. Если id там уже есть — не добавляй повторно.
- Строку производной потребности не трогай.
- `depends on` не заполняй ни у той, ни у другой.

Направление здесь не определяется. Слова «раньше», «предшественник»,
«направление не определено» в этой части не применяются: корневая
потребность не веха, она не наступает раньше или позже.

## Часть 4. Зависимости (случай З)

Кто ниже на доске, тот наступает раньше и является предшественником:
запиши id нижнего в `depends on` верхнего.

Сравнивай центры по вертикали, а не годовые полосы.

Если центры совпадают с точностью до нескольких пикселей — запиши
в `Примечания` обоих «связь с N, направление не определено»
и вынеси пару на уточнение.

## Часть 5. Цвет линий

Линия — самостоятельный объект канвы. Она **не принадлежит фрейму**:
в SVG для записи её элемент лежит на верхнем уровне документа,
а не внутри `<g>` фрейма.

Для каждой линии случая Р, у которой `stroke` не равен `#e7e7e7`,
отправь обновление вида:

    <svg xmlns="http://www.w3.org/2000/svg">
    <line data-miro-id="ID_ЛИНИИ"
          data-start="ID_СТИКЕРА_A"
          data-end="ID_СТИКЕРА_B"
          stroke="#e7e7e7" stroke-width="2.0" />
    </svg>

Все линии одной операцией. После записи перечитай область и убедись,
что цвет изменился.

## Что вернуть

1. Список классификации линий из части 2, целиком.
2. Заведённые строки.
3. Отложенные на уточнение: решения вместо потребностей и хотелки.
4. Случаи Х и связи без определимого направления.
5. Расхождения: id в `дети` или `depends on`, которому не соответствует
   ни одна линия на доске. Не удаляй такие значения, только доложи.
6. Какие линии перекрашены и какие остались прежнего цвета.
